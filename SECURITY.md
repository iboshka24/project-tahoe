# SECURITY.md — Project Tahoe

> Статус: политика этапа фундамента. Угрозы описаны честно, включая те,
> которые мы пока не закрываем.

---

## 1. Модель угроз (кратко)

| Угроза | Наш ответ сегодня |
|---|---|
| Вредоносный PE/Mach-O/AppImage | Запуск только через UEL как непривилегированный процесс; AppImage помечается непесочницей |
| Подмена интерпретатора `binfmt_misc` | Наши записи используют абсолютные пути + флаг `F` там, где нужно; порядок записей документирован |
| Setuid через `binfmt_misc` | Мы не ставим флаг `C`; учётные данные наследует интерпретатор, бинарник — нет |
| Подмена Wine/Darling в PATH | UEL ищет их по явным путям, версии фиксирует в отчёте |
| Неподписанные пакеты | Только подписанные репозитории, `archlinux-keyring` + собственный ключ Tahoe |
| Утечка данных через порталы | Минимальные `finish-args`, без `--filesystem=host` по умолчанию |

## 2. Что мы знаем про `binfmt_misc` (проверено по документации ядра)

- Сопоставление — **байтовое по смещению + AND-маска**, не парсинг.
  Семантической диспетчеризации (`e_type`, `e_machine` как поля) нет.
- Magic обязан лежать в первых 128 байтах; `PE\0\0` обычно вне окна —
  поэтому регистрируемся только на `MZ` (для Wine).
- Порядок важен: **позже добавленная запись совпадает первой**.
  Наши файлы в `binfmt.d/` именуются так, чтобы порядок был детерминирован.
- `O`/`C` флаги доверяют интерпретатору содержимое/права бинарника —
  мы их не используем.
- Известные CVE: CVE-2026-68186 (DoS через `O` + FUSE, исправлено в
  6.12.101 / 6.18.42 / 7.1.6), CVE-2026-74618 (WARN через чужой userns).
  Оба закрыты на актуальных ядрах; требуем ядро с исправлениями.
- CVE-2021-22505 — **не** про `binfmt_misc` (это Netfilter). Не цитировать.

## 3. AppImage — не песочница

Формат не предоставляет изоляции, сигнатура опциональна и рантаймом не
проверяется. Tahoe:

- запускает AppImage только через UEL с `Confidence::Speculative` и явным
  предупреждением;
- предпочитает `--appimage-extract-and-run` там, где нет FUSE;
- никогда не ставит AppImage в автозапуск без согласия пользователя.

## 4. Wine / Darling

- Каждый — отдельный непривилегированный процесс, свой префикс
  (`WINEPREFIX` / `DPREFIX`), свои env, лимиты через cgroup (этап 2).
- Префиксы пересоздаваемые; повреждение префикса не затрагивает систему.
- Darling — только userspace (`darlingserver`), модуля ядра нет с 2022 года;
  нечего поддерживать в DKMS.

## 5. Сообщение об уязвимостях

Пока проект без выделенной security-команды: создавайте приватный issue
или пишите мейнтейнеру напрямую. Цель ответа — 7 дней. Не публикуйте
эксплойт до исправления.

## 6. Что НЕ обещаем

- Песочницу для AppImage (её нет в формате).
- Проверку подписей AppImage при запуске (рантайм её не делает).
- Совместимость Wine/Darling как границу безопасности — это слои
  совместимости, а не изоляция. Для недоверенного кода используйте
  Flatpak или VM.
