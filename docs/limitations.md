# Ограничения — Project Tahoe

> Нормативный документ. Всё, что здесь перечислено, **не работает или
> работает не полностью**, и это отражено в коде (через `Refused`,
> `Speculative`, `Layer{caveat}` или явный комментарий), а не спрятано.
>
> Обновлено: 2026-10-14 (сессия 3).

---

## 1. Композитор

| Ограничение | Детали |
|---|---|
| Нет TTY-бэкенда в `main` | Фичи `drm/gbm/egl/libinput/session_libseat/udev` **компилируются** (`cargo check --features tty`), но не подключены к запуску. Только `headless` и `winit`. |
| Нет курсора | `wl_cursor`/`wp_cursor_shape` не реализованы; в winit-режиме виден системный курсор хост-сессии, в TTY курсора не будет. |
| Нет `xdg-decoration` | Клиенты рисуют свои рамки (CSD). `zxdg_decoration_manager_v1` и `org_kde_kwin_server_decoration` не зарегистрированы. Для Flatpak это допустимо (декорации там не обязательны). |
| Нет popup-grab | `XdgShellHandler::grab`/`reposition_request` — пустые. Контекстные меню и выпадающие списки появятся, но не будут захватывать ввод. |
| Нет resize | `resize_request` не обрабатывается: окна нельзя тянуть за угол. Перемещение (Super+drag и `move_request`) работает. |
| Нет maximize/fullscreen/minimize | Запросы принимаются, но состояние не меняется. |
| Нет вывода за экран | Один `wl_output`, без `wlr-output-management`. |
| Нет Xwayland | Фича включена в `tty`, но окно Xwayland не создаётся. |
| Нет `wl_drm`/`linux-dmabuf` | Только `wl_shm`. Клиенты с аппаратным ускорением будут падать на программный путь (или не запускаться, если требуют dmabuf). |
| Нет скриншотов/скринкаста | Протоколы `ext-image-copy-capture`, `wlr-screencopy` не реализованы. Файлы в `~/Pictures/tahoe` — не снимок вывода композитора, а CPU-рендер оболочки; см. §2. |
| Нет `xdg_foreign` | Порталы не смогут связать свой диалог с окном; спецификация разрешает пустой `parent_window`. |

## 2. Оболочка (Tahoe Shell)

| Ограничение | Детали |
|---|---|
| Нет GUI | Существуют модель (`Dock`, `Workspaces`, `LauncherIndex`, `finder`), рендерер и сцены. Ни одного `wl_surface` оболочка пока не создаёт — это следующая задача, а не забытая. |
| Нет панели в layer-shell | `zwlr_layer_shell_v1` обрабатывается композитором, но клиента-панели нет. |
| **Скриншоты — не скриншоты сессии** | `tahoe-preview --scene all` рисует раскладку, палитру и шрифты **тем же кодом, что их определяет**, но окна на картинке — заглушки, а не `wl_surface` настоящих клиентов. Отказы, которые рендер не покажет и которые важнее всего: клиент не прислал буфер, seat не доставил ввод, окно нарисовалось под панелью. |
| Текст рисуется, но не компонуется шейдером | Глифы растрирует `ab_glyph` в CPU-буфер. Аппаратного пути и кэша глифов в GL нет. |
| Сглаживание — только grayscale | Субпиксельный рендеринг требует знать порядок RGB-полос, которого композитор знать не может. |
| Нет иконок | Плитки показывают первую букву имени: рисованная «примерная» иконка была бы худшей ложью, чем буква. Иконочной темы в системе нет. |
| Нет анимаций | Кадр статичен, поэтому скриншоты вообще что-то значат. |
| Один вес шрифта вместо двух | Если жирного начертания нет, молча берётся обычное. Десктоп, который не стартует, хуже десктопа с одним весом. |
| PNG пишется без сжатия | `Canvas::to_png` использует stored-блоки deflate: валидно, без зависимостей, 6.4 МБ на кадр 1600×1000. `tests/png-compress.py` ужимает те же пиксели до ~70 КБ; потерянность проверяется побайтовым сравнением распакованных строк. |
| Тёмная тема по умолчанию | `DesignSystem::from_env()` при `auto` всегда выбирает тёмную: портал Settings, который сообщил бы реальное предпочтение пользователя, не реализован. |
| Finder без GUI | `finder` полностью функционален как библиотека; окна нет. |
| Нет корзины | `delete()` удаляет по-настоящему. Trash-бэкенд по Freedesktop не реализован; `PendingDelete` даёт подтверждение, но не отмену. |
| Нет предпросмотра (Quick Look) | Не начато. |

## 2. ISO (сессия 19.10)

| Ограничение | Детали |
|---|---|
| Образ из CI | Собран и загружен: `b95bb0f`, run 39511318414, ISO SHA-256 `0e600270…67ed6`. Живёт как артефакт с retention 1 день (см. «Релиза нет»). |
| UEFI не проверен | В каталоге El Torito есть EFI-секция, но OVMF в этой сессии недоступен; все загрузки и установка — BIOS/MBR. |
| `systemd-binfmt.service` | Исправлено: правило собиралось из тега `v0.1.0` (на 18 коммитов позади) и указывало на несуществующий `/usr/bin/wine`; сборка `142ad4d` берёт HEAD, и на ISO 2026-10-20 `systemctl --failed` пуст. На установленной системе сервис `active`, правило `:tahoe-wine-pe:M::MZ::/usr/lib/tahoe/tahoe-dispatch:P`. |
| Обои: hyprpaper 0.8.4 падал | На образе 2026-10-20 рабочий стол был **чёрным**: hyprpaper 0.8.4 (hyprtoolkit/Aquamarine) требует GBM/EGL, в QEMU без 3D падает с `Failed to acquire a buffer` и SIGSEGV. Переведено на `swaybg` + `WLR_RENDERER=pixman`. На ISO `b95bb0f` и на установленной системе обои закрывают весь экран 1280×800, `pgrep -a swaybg` показывает процесс. |
| Релиза нет | ISO живёт как артефакт CI с `retention-days: 1`; `gh release view v0.1.0` → `release not found`. |
| **Установщик: установка проходит, железо — нет** | Calamares 3.4.2 собирается из AUR в CI. На ISO `b95bb0f` чистая установка на новый 24 GiB qcow2 прошла **без ручных правок**; диск загрузился сам до `tahoe-vm login:`, вход → рабочий стол, `systemctl --failed` пуст (`docs/iso-installer.md` §9). UEFI не проверен, хост BIOS/MBR. **Не ставить на железо.** |
| `/etc/calamares` остаётся на цели | `branding/`, `modules/`, `settings.conf` копируются `unpackfs` и не удаляются cleanup-задачей. Автоматически ничего не запускают; косметика, задача в `TODO.md`. |

## 2a. Universal execution (сессия 2)

| Ограничение | Детали |
|---|---|
| ~~Ни один PE не запущен~~ | **Устарело:** настоящий PE, собранный clang + lld-link, отработал под Wine 11.0 и под Proton-CachyOS, exit 0. Подтверждено `tests/dispatch-e2e.sh`. |
| Ни один Mach-O не запущен | Darling не установлен. Это единственная оставшаяся дыра в «нативном» запуске. |
| DMG не монтируется | Трейлер и `blkx` разобраны; извлечение делегировано внешнему инструменту, которого нет. |
| APFS не поддерживается | Нет в mainline; только read-only FUSE вне ядра. |
| **UNVERIFIED**: «типичный современный DMG — это APFS» | Официального утверждения Apple или образца не проверяли. |
| `.lnk` парсится частично | Заголовок + `StringData`. `LinkTargetIDList` не резолвится — это делает `wine start`. |
| Реальные `.lnk` от инсталляторов не проверялись | Фикстуры синтезированы по MS-SHLLINK. |
| `hfsplus`/`apfs` не парсятся | Сознательно делегированы внешним инструментам. |
| `.xip`/`pbzx` не распаковываются | Формат описан, код не написан. |
| Wayland-драйвер Wine не включён | Upstream считает его экспериментальным; Tahoe не переопределяет список драйверов. |
| Ядерные флаги 7.3 (`T`/`L`/`B`) не используются | Только в 7.3; эмитить неизвестный флаг — значит сломать всю регистрацию. |
| `binfmt.d/` не устанавливается тестами | Нужен root. Тесты проверяют генерацию строк, а не установку. |

## 2b. Apple-приложения (сессия 3)

| Ограничение | Детали |
|---|---|
| iOS-приложение **не собиралось** | Нет iOS SDK. SDK требует Apple ID и ~7 ГБ. |
| View-файлы **не компилировались** | Только синтаксический разбор (`swiftc -parse`). Семантическую ошибку в теле view компилятор не поймает — SwiftUI на Linux нет. |
| Токены и модель — **проверены** | `swift build --target TahoeDesign` + `swift test`: 21 тест. Это закрыто. |
| iOS `.app` **нельзя запустить на Linux** | Он линкует UIKit, которого не реализует ни Darling, ни что-либо ещё. Запуск требует реального iPhone. |
| Симулятора на Linux нет | xtool документирует `--simulator` только под macOS. |
| `Info.plist` не сверялся с настоящим | Фикстура смоделирована по `Packer.swift` из xtool, а не снята с запуска. |
| `swift test` не запускался | Тесты токенов написаны, но не исполнялись. |
| Apple SDK не распространяется | xtool не говорит, можно ли делиться извлечённым SDK. Не считать разрешённым. |

## 2c. COSMIC (сессия 4)

| Ограничение | Детали |
|---|---|
| Тема **не проверена на живом COSMIC** | COSMIC не установлен. Все утверждения — о файлах, а не о десктопе. |
| Анимации, радиус индикатора, размеры апплетов | Жёстко в Rust. Недостижимы без форка — перечислено в `docs/cosmic-theming.md`. |
| Лаунчер и апплеты | Отдельные репозитории, не аудированы. Не считать настраиваемыми. |
| Прокрутка темы для Flatpak | `cosmic-config` ищет `HOST_XDG_CONFIG_HOME` — не проверялось. |

## 3. Universal Execution Layer

| Ограничение | Детали |
|---|---|
| Wine не проверен на реальном запуске | В окружении разработки Wine нет. Код строит команду и супервизор её запускает, но **ни один PE не был запущен**. См. `docs/windows-compatibility.md` §5. |
| Darling: командная строка не проверена | `darling <program>` + `DPREFIX` взяты из README upstream, а не из наблюдения. Помечено в коде (`supervisor.rs`). |
| FEX / box64: точный CLI не проверен | Используются `FEXInterpreter` и `box64` как имена; флаги не проверялись. Помечено. |
| Нет `binfmt_misc`-интеграции в рантайме | Файлы в `binfmt.d/` существуют, но не устанавливаются: нужен root. UEL не полагается на порядок binfmt. |
| Нет DMG-монтирования | `ObjectFormat::Dmg` распознаётся и **отвергается**. Код пути «смонтировать → найти .app → probe» не написан. |
| FAT-заголовок Mach-O не диспетчеризуется | `0xCAFEBABE` возвращается как `Ambiguous` и отвергается: отличить universal binary от Java-класса по 128 байтам нельзя. |
| Нет cgroup-лимитов | Тайм-аут и группа процессов есть; ограничений по памяти/CPU нет. |
| Нет GUI-интеграции | Супервизор не вызывается из оболочки — только из CLI. |

## 4. Дистрибутив

| Ограничение | Детали |
|---|---|
| ISO не собран | `iso/` — профиль archiso; `mkarchiso` не запускался (пакет не установлен). |
| Пакеты не собраны | `packages/*/PKGBUILD` синтаксически проверены (`makepkg --printsrcinfo`, `bash -n`), но не собирались. |
| Нет репозитория | `[tahoe]` в `iso/pacman.conf` — заглушка URL. |
| Нет установщика | `archinstall` не адаптирован. |
| Нет `systemd-sysupdate` | Атомарные обновления не настроены. |

## 5. Что никогда не будет реализовано

См. ADR:

- собственный загрузчик PE/Mach-O (ADR-0005);
- собственный пакетный менеджер (ADR-0003);
- исполнение `.dmg` или `.app` как бинарников (ADR-0004);
- линковка GPL-кода в наши бинарники (LICENSING.md §3);
- обещание совместимости без измерений (ADR-0006).
