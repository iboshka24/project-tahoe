# ADR-0008: Rootless, namespaced `binfmt_misc` instead of a kernel patch

- Статус: принято (2026-10-14).
- Контекст: нужна диспетчеризация не-ELF форматов на уровне ядра.
  Варианты: (a) патч ядра с новым `linux_binfmt`, (b) системные записи
  `binfmt_misc` через root, (c) `binfmt_misc` внутри user namespace,
  (d) отказ от ядерной диспетчеризации.
- Решение: **(c)** для пер-приложений и **(b)** как статические файлы в
  `binfmt.d/` для системных случаев. Патч ядра не делаем.
- Причины:
  - с Linux 6.7 (`21ca59b365c0`) `binfmt_misc` монтируется в userns
    (`FS_USERNS_MOUNT`, суперблок на namespace). Проверено на 6.18.55:
    регистрация без root работает, запись исчезает с namespace, хост не
    меняется — всё это покрыто тестами;
  - Linux 7.3 уже несёт семантическую диспетчеризацию (BPF `B`-обработчик,
    `match()` читает произвольные смещения) и флаги `T`/`L`. Патч
    дублировал бы смерженное;
  - регистрация `linux_binfmt` из userspace не появится никогда: upstream
    выбрал BPF `struct_ops`;
  - в области binfmt за 2022–2026 восемь CVE; тащить своё — значит
    наследовать их вечно.
- Последствия: правила используют только флаги, понятные стабильным ядрам
  (`P`, `O`, `C`, `F`). `T`/`L`/`B` — пункт дорожной карты, не зависимость.
  Свой загрузчик PE/Mach-O по-прежнему запрещён (ADR-0005).
