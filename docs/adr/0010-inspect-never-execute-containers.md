# ADR-0010: Контейнеры инспектируются, а не исполняются

- Статус: принято (2026-10-14). Уточняет ADR-0004 для более широкого
  набора форматов.
- Контекст: кроме `.dmg` появились `.pkg`/`.xip` (XAR), `.msi` (OLE2),
  plist и `.app` (каталог).
- Решение: введена отдельная стратегия `Strategy::Inspect`, отличная от
  `Rejected`. Она означает «мы точно знаем, что это, и знаем, что делать»,
  а не «мы не поняли, отказываемся». Для `.msi` — отдельная
  `Strategy::WineInstaller`, потому что это другой *процесс* с другими
  аргументами. Для `.app` — `Strategy::MacBundle`, потому что исполнять
  нужно внутренний файл, а не каталог.
- Причины:
  - `execve` каталога не работает; угадывать исполняемый файл по размеру —
    ошибка в остальных случаях;
  - `.msi` — это база данных, которую читает программа-установщик, а не
    программа;
  - различие «отказ от неизвестного» и «инструкция для известного» важно
    для UI: первое — ошибка, второе — подсказка;
  - `Confidence::Verified` для `Inspect` подчёркивает, что это не
    неуверенность.
- Последствия: подсказка `Inspect` несёт полезные факты (сегменты DMG,
  метод сжатия, наличие LZFSE), а не общий текст. Есть тесты на все ветки.
